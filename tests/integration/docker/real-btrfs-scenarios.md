# Real-Btrfs scenario manifest

This manifest tracks the staged migration from `real-btrfs-test.sh`. The shell
scenario remains authoritative until every row has a C++ owner and parity has
been verified in the privileged container.

| Scenario | Setup | Public invocation | Exit | Expected artifacts and Btrfs state | Cleanup | Kernel capabilities | Owner |
|---|---|---|---|---|---|---|---|
| Full backup | Separate owned loop devices; Btrfs source; LUKS2/Btrfs target; two source files | `btrfs-backupctl runner execute` | 0 | JSON says completed/non-incremental; one read-only local snapshot; one committed received snapshot; matching content and UUID lineage; empty `.incoming` | Unmount both filesystems, close owned mapper, detach owned loops, remove marked root | loop, device-mapper, mount, Btrfs snapshot/send/receive | `RealBtrfsBackupTests.cpp` |
| Incremental backup | Completed full backup, then mutate and add source files | `btrfs-backupctl runner execute` with a new timestamp and run id | 0 | JSON says completed/incremental; two matching local and remote snapshots; latest received UUID points to latest local UUID | Same owned-resource teardown after the scenario sequence | loop, device-mapper, mount, Btrfs incremental send/receive | `RealBtrfsBackupTests.cpp` |
| Interrupted receive | Completed full and incremental backups; create an actual partial Btrfs subvolume below the source-specific incoming run directory | `btrfs-backupctl runner execute` with a third timestamp and run id | 0 | JSON says completed/incremental; stale incoming subvolume and its run directory are removed; no `.incoming/home` children remain; committed repository remains valid | Same owned-resource teardown; fixture cleanup refuses foreign loops or an unmarked root | loop, device-mapper, mount, Btrfs subvolume cleanup/send/receive | `RealBtrfsBackupTests.cpp` |

| Provisioning interruption matrix | Owned device prepared for every destructive transaction stage | Public manager provisioning API, cancelled/stopped after each stage | failed or cancelled according to stage | Accurate terminal state; no prematurely published profile; resumable recovery metadata | Verify and release only resources recorded as fixture-owned at that stage | loop, partition scan, device-mapper, udev, D-Bus | shell, stage 12 |

All test roots are disposable and uniquely named. C++ fixtures must report
cleanup errors from explicit `close()`; destructors are best-effort `noexcept`
fallbacks only.
